## How it works

The proposed Video Poker design is a five-card draw poker game with a VGA display. The display shows the dealt cards, which cards are held, the player's credit balance, and the result of each round. A 25 MHz input clock drives the game logic and VGA controller.

The player starts with 100 credits. Pressing the Deal/Draw button starts a round, deducts a fixed wager of 5 credits, and deals five cards. Five active-high switches select the cards to hold. Pressing the button again keeps the selected cards and replaces the others. The final hand is evaluated, and its payout is added to the remaining balance.

The payout schedule for one 5-credit wager is:

| Hand | Payout (credits) |
| --- | ---: |
| Royal flush | 4000 |
| Straight flush | 250 |
| Four of a kind | 125 |
| Full house | 45 |
| Flush | 30 |
| Straight | 20 |
| Three of a kind | 15 |
| Two pair | 10 |
| Pair of jacks or better | 5 |
| All other hands | 0 |

For example, a player starting with 100 credits who receives two pair finishes the round with `100 - 5 + 10 = 105` credits.

Cards are generated by a pseudorandom number generator (PRNG) and deck-management logic. The PRNG seed is supplied on `uio_in[7:0]` and sampled when reset occurs. The active-low asynchronous reset also restores the initial game state and the 100-credit balance. The bidirectional pins are used as inputs, with `uio_out[7:0]` and `uio_oe[7:0]` both driven to zero. The Deal/Draw pushbutton input is debounced.

## How to test

### Connections

| Pin | Function |
| --- | --- |
| `clk` | 25 MHz system and VGA pixel clock, rising edge |
| `rst_n` | Active-low asynchronous reset |
| `ena` | Project enable; hold high during operation |
| `ui_in[0]` through `ui_in[4]` | Hold cards 1 through 5 respectively; high means hold |
| `ui_in[5]` | Active-high Deal/Draw pushbutton |
| `ui_in[6]`, `ui_in[7]` | Unused |
| `uio_in[7:0]` | 8-bit PRNG seed |
| `uo_out[0]`, `uo_out[4]` | VGA red channel, two bits |
| `uo_out[1]`, `uo_out[5]` | VGA green channel, two bits |
| `uo_out[2]`, `uo_out[6]` | VGA blue channel, two bits |
| `uo_out[3]` | VGA vertical sync |
| `uo_out[7]` | VGA horizontal sync |

### Playing a round

1. Connect the VGA interface, five hold switches, Deal/Draw button, and seed inputs. Supply a 25 MHz clock and set `ena` high.
2. Set the desired seed on `uio_in[7:0]`. Set the hold switches and Deal/Draw input low. Assert `rst_n` low, keeping the seed stable during reset, then release reset by setting `rst_n` high. Verify that the displayed balance is 100 credits.
3. Press and release Deal/Draw. Verify that five cards appear and the balance decreases to 95 credits.
4. Set each hold switch high for a card you want to keep, or low for a card you want to replace. Verify that the display identifies the selected cards.
5. Press and release Deal/Draw again. Verify that held cards remain unchanged, the other cards are replaced, and the display shows the final hand's result. Check that the balance equals the balance before the round minus 5 credits plus the payout from the table above.
6. Start another round and verify that the balance carries over. Assert reset again to verify that the game returns to its initial state and restores 100 credits.

For directed testing, hold all five cards to check that a draw preserves the entire hand, then test individual hold switches and combinations. Check that dealing and drawing do not produce duplicate cards within a hand, that a single button press causes one action, and that each hand category pays the listed amount. Using the same seed after reset allows repeatable PRNG tests; keep the input sequence and timing consistent when comparing runs.

## External hardware

- A Tiny Tapeout development board or compatible setup providing the 25 MHz clock, project enable, and reset signals.
- A VGA display and an interface that connects the six RGB outputs and two sync outputs to the display. The RGB interface must provide the appropriate resistor network or VGA DAC.
- Five switches for the card hold inputs.
- One active-high pushbutton for the Deal/Draw input.
- Eight switches or another source of a stable 8-bit seed for development and testing. The proposal intends these seed controls to be inaccessible to the player in a production setup.
